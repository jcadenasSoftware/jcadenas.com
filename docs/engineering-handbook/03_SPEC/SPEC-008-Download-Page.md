# SPEC-008 — Download Page

**Estado:** Aprobado

**Versión:** 1.0

**Fecha:** 2026-08-08

**Proyecto:** Xpendz

---

# 1. Objetivo

Definir la especificación de producto de la página **Download** del sitio público de Xpendz.

Esta página existe para transformar confianza en instalación.

Su misión es hacer que comenzar a usar Xpendz se sienta obvio, simple y con la menor fricción posible.

No debe reiniciar la historia del producto.

No debe volver a argumentar por qué Xpendz existe.

No debe competir con las páginas cuya misión ya fue generar interés, comprensión y confianza.

Su responsabilidad es eliminar la incertidumbre final entre la decisión y la acción.

El proceso de instalación forma parte de la experiencia de producto.

---

# 2. Contexto

Este documento se basa en:

- RFC-003 Website Information Architecture
- UX-013 Website Information Flow
- SPEC-006 Features Page
- SPEC-007 Privacy & Security Page
- UX-010 Final CTA Strategy

RFC-003 estableció que Download debe convertirse en una superficie pública propia dentro de la arquitectura del sitio.

UX-013 definió que, después de descubrir, comprender y confiar, el visitante necesita una superficie dedicada para decidir e instalar.

SPEC-006 delimitó la responsabilidad de la página Features como espacio para comprender utilidad, no para resolver la instalación.

SPEC-007 delimitó la responsabilidad de la página Privacy & Security como espacio para construir confianza, no para explicar el inicio operativo.

UX-010 estableció un principio fundamental que aplica directamente a esta página:

si el recorrido previo cumplió su trabajo, el usuario ya tomó la decisión.

Ahora solo necesita comenzar.

Como consecuencia, esta página debe actuar como el puente claro entre el sitio público y la primera experiencia real dentro del producto.

---

# 3. Pregunta principal que responde

La página Download responde una sola duda central.

**¿Cómo empiezo a usar Xpendz?**

También debe poder responder, de forma natural, esta variante de la misma pregunta:

**¿Qué pasa después de instalarlo?**

No debe actuar como catálogo de funcionalidades.

No debe convertirse en documentación técnica.

No debe abrir debates secundarios que ya debieron resolverse antes.

---

# 4. Criterios de éxito

Después de recorrer esta página el visitante deberá:

- saber exactamente dónde instalar la aplicación;
- entender en qué plataformas está disponible;
- comprender los requisitos básicos para comenzar;
- sentirse confiado para iniciar;
- no tener dudas sobre el siguiente paso.

La página será exitosa si convierte decisión en acción sin fricción innecesaria.

---

# 5. Rol dentro del recorrido público

La página Download ocupa la transición entre el sitio público y la primera experiencia de uso.

El recorrido esperado es el siguiente.

Landing

↓

Features

↓

Privacy & Security

↓

Download

↓

First Launch

Landing genera interés.

Features crea comprensión.

Privacy & Security crea confianza.

Download elimina incertidumbre operativa.

First Launch comienza la experiencia real del producto.

Por lo tanto, esta página no debe sentirse como otra pieza promocional del sitio.

Debe sentirse como la puerta de entrada al uso.

---

# 6. Estructura narrativa

La página deberá remover fricción de manera progresiva.

No deberá presentarse como una acumulación de enlaces, botones o mensajes desconectados.

Debe acompañar al visitante desde la disposición para comenzar hasta el inicio efectivo del uso.

El recorrido narrativo recomendado será el siguiente.

Listo para comenzar

↓

Plataformas disponibles

↓

Proceso de instalación

↓

Qué ocurre después de instalar

↓

Dónde obtener ayuda

↓

Comenzar a usar Xpendz

Cada etapa deberá responder una duda práctica antes de introducir la siguiente.

La página no debe pedir más convicción.

Debe convertir convicción en movimiento.

---

# 7. Secciones de contenido

La página deberá organizar su contenido mediante secciones claras y progresivas.

Cada sección deberá explicar:

- su propósito;
- la preocupación del usuario que responde;
- el valor que entrega.

Las siguientes secciones representan la estructura recomendada.

## 7.1 Introducción de descarga

### Propósito

Confirmar que el visitante llegó al lugar correcto para comenzar a usar Xpendz.

### Preocupación del usuario que responde

El visitante necesita una validación inmediata de que ya no debe seguir evaluando, sino iniciar el proceso.

### Valor que entrega

Reduce fricción cognitiva.

Transforma la decisión tomada en un siguiente paso claro.

## 7.2 Disponibilidad por plataforma

### Propósito

Explicar con claridad en qué plataformas está disponible actualmente Xpendz y cuáles forman parte de una evolución futura.

### Preocupación del usuario que responde

El visitante necesita saber si puede usar la aplicación en su dispositivo actual o si debe esperar otra plataforma.

### Valor que entrega

Evita confusión.

Ordena expectativas desde el primer momento.

## 7.3 Google Play

### Propósito

Presentar el camino principal de instalación disponible hoy cuando Android sea la plataforma activa.

### Preocupación del usuario que responde

El visitante quiere saber cuál es el enlace real, oficial y confiable para comenzar la instalación.

### Valor que entrega

Concentra la acción en una referencia directa y verificable.

## 7.4 Plataformas futuras

### Propósito

Mostrar que el producto puede crecer hacia nuevas plataformas sin confundir disponibilidad presente con disponibilidad futura.

### Preocupación del usuario que responde

El visitante necesita distinguir entre lo que puede usar ahora y lo que podría existir más adelante.

### Valor que entrega

Aporta transparencia.

Evita promesas ambiguas y reduce decepción posterior.

## 7.5 Requisitos de instalación

### Propósito

Explicar las condiciones básicas necesarias para comenzar la instalación o uso inicial.

### Preocupación del usuario que responde

El visitante quiere saber si necesita algo específico antes de descargar o si encontrará barreras inesperadas.

### Valor que entrega

Previene incertidumbre práctica antes del primer paso.

## 7.6 Expectativas del primer inicio

### Propósito

Explicar de forma simple qué ocurrirá después de instalar y abrir la aplicación por primera vez.

### Preocupación del usuario que responde

El visitante quiere una idea clara de lo que encontrará una vez que salga del sitio público y entre al producto.

### Valor que entrega

Suaviza la transición entre instalación y uso.

Hace que el inicio se sienta esperado y comprensible.

## 7.7 Creación de cuenta

### Propósito

Explicar, a nivel de producto, cómo comienza la relación del usuario con Xpendz cuando necesita registrarse o identificarse.

### Preocupación del usuario que responde

El visitante quiere saber si el inicio implicará pasos adicionales y qué papel cumple la cuenta dentro de la experiencia.

### Valor que entrega

Reduce sorpresa.

Prepara al usuario para comenzar con claridad.

## 7.8 Sincronización

### Propósito

Explicar si la experiencia inicial incluye continuidad entre dispositivos o persistencia de información, desde una perspectiva de uso y no de implementación.

### Preocupación del usuario que responde

El visitante necesita entender qué continuidad puede esperar una vez que empiece a usar Xpendz.

### Valor que entrega

Conecta instalación con continuidad futura.

Evita que el usuario imagine un proceso aislado o incierto.

## 7.9 Soporte

### Propósito

Orientar al visitante hacia la ayuda correcta si encuentra dudas o bloqueos durante el inicio.

### Preocupación del usuario que responde

El visitante necesita saber que no quedará sin salida si algo no sale como esperaba.

### Valor que entrega

Aporta respaldo.

Reduce la sensación de riesgo al comenzar.

---

# 8. Principios de diseño

La página Download deberá respetar los siguientes principios.

## 8.1 Fricción mínima

Cada bloque debe ayudar a que comenzar resulte más simple.

## 8.2 Acción clara

La acción principal debe ser inequívoca.

## 8.3 Sin marketing repetido

La página no debe reabrir el discurso de adquisición.

## 8.4 Sin inventario funcional

La descarga no debe mezclarse con una nueva explicación extensa del producto.

## 8.5 Sin contenido legal

La página no debe absorber responsabilidades que pertenecen a la Política de Privacidad u otras superficies legales.

## 8.6 Enlaces reales

La confianza depende de que la acción conduzca a superficies oficiales, claras y directas.

## 8.7 Claridad de plataforma

La disponibilidad actual debe ser comprensible en segundos.

## 8.8 Decisión rápida

La página debe ayudar a actuar pronto.

No a seguir dudando.

---

# 9. Relación con la Landing

La Landing crea deseo.

Download habilita acción.

Por esa razón, la página Download nunca deberá repetir el Hero ni reconstruir la promesa principal del producto.

Su deber es recoger la decisión ya preparada y convertirla en un inicio claro.

Si un visitante llega a esta página después del recorrido principal, debe sentir continuidad.

Nunca reinicio.

---

# 10. Relación con Features

Features explica por qué Xpendz resulta útil.

Download explica cómo comenzar.

Ambas páginas se complementan, pero no deben compartir la misma responsabilidad.

Features profundiza comprensión.

Download elimina fricción operativa.

---

# 11. Relación con Privacy & Security

Privacy & Security reduce miedo.

Download elimina la incertidumbre operativa que todavía puede quedar después de confiar.

La primera responde:

¿puedo instalar esto con tranquilidad?

La segunda responde:

¿cómo empiezo ahora mismo?

Si ambas superficies se mezclan, la claridad final disminuye.

---

# 12. Antipatrones

La página Download no deberá:

- repetir la descripción general del producto;
- listar funciones extensamente;
- abrir discusiones sobre precios o planes si no son necesarias para iniciar;
- convertirse en superficie legal;
- utilizar exageración de marketing;
- presentar múltiples CTAs principales que compitan entre sí;
- conducir a enlaces muertos o ambiguos;
- ocultar o volver confusa la disponibilidad por plataforma;
- alargar la decisión con contenido que ya pertenece a otras páginas.

Si aparece cualquiera de estos patrones, la página deberá replantearse.

---

# 13. Evolución futura

La página Download deberá poder crecer hacia nuevas plataformas y nuevos canales de distribución sin alterar su estructura narrativa principal.

Toda evolución futura deberá fortalecer la claridad del inicio, no fragmentarla.

Ejemplos de evolución posible:

- edición de escritorio;
- iOS;
- versión web;
- instaladores directos;
- programa beta;
- early access;
- TestFlight;
- Windows;
- Linux;
- macOS.

Toda nueva capacidad deberá cumplir al menos estas condiciones:

- dejar absolutamente clara su disponibilidad real;
- integrarse dentro de la misma secuencia narrativa de inicio;
- mantener una acción principal comprensible por plataforma;
- diferenciar claramente entre acceso actual y acceso futuro;
- preservar el principio de que instalar también es parte de la experiencia de producto.

La escalabilidad de esta página no dependerá de sumar más botones sin criterio.

Dependerá de conservar un inicio simple, guiado y confiable aunque existan más plataformas.

Este documento complementa:

- UX-013 Website Information Flow;
- SPEC-006 Features Page;

- UX-010 Final CTA Strategy.

RFC-003 define por qué Download existe como superficie propia dentro de la arquitectura pública.

Este SPEC define la referencia canónica para cualquier futura implementación de la página Download.

---

# 15. Documento vivo

Toda modificación importante de la página Download deberá reflejarse primero en este documento antes de trasladarse a contenido, diseño o implementación.

Su propósito es preservar claridad, continuidad y baja fricción en toda evolución futura.

Mientras Xpendz incorpore nuevas plataformas o nuevos canales de distribución, esta página podrá ampliarse.

Pero su misión deberá permanecer constante:

Ayudar al visitante a comenzar a usar Xpendz de forma clara, simple y confiada, recordando siempre que el proceso de instalación también forma parte de la experiencia del producto.
